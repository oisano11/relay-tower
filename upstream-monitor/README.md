# 🗼 中转塔台 (Relay Tower) (Upstream Monitor & Switcher Console)

专为 AI 中转站运营设计的上游通道智能监控与调度中枢。

## 🌟 核心功能

1. **中控台随时显示上游倍率**
   - 实时大盘展示各上游渠道当前成本倍率（如 `0.65x`, `0.85x`, `1.10x`）。
   - 自动定时探活与测速，实时展示上游网络延迟（ms）及连通性状态。
   - 支持主流 New-API / One-API `/api/pricing` 价格探针，支持随时添加、编辑和删除上游渠道。

2. **上游倍率调整弹窗提醒**
   - 定时差分检查上游调价动作（上涨或下调）：倍率默认每 5 分钟检查，通道探活默认每 3 小时执行，也可手动触发。
   - 居中弹出强警示度模态弹窗，展示 `变动渠道`、`原倍率 -> 新倍率` 及 `涨跌百分比`。
   - 结合 Web Audio 合成声效警报。
   - **高危涨价预警**：当变价通道是当前主力出海通道时，触发红色警示，并提供“一键切换到更低倍率备选通道”快捷操作。
   - 完整记录历次调价审计流水（Audit Log）。

3. **一键切换使用那条上游通道与安全代理网关**
   - 中控台所有卡片及顶部快捷下拉框均支持“一键设为主用”。
   - **内置安全反向代理网关 (Smart Proxy Gateway)**：
     - 开放统一 API 入口：`http://localhost:3300/v1`
     - 客户端（如 Claude Code CLI、Cursor、CC Switch、Chatbox 等）配置此入口后，切换主调会让后续请求使用新上游，无需修改客户端入口；已有请求不会迁移，失败请求可能需要重试。
     - **🛡️ 专属网关密钥鉴权 (Gateway API Key)**：外部请求调用 `/v1/*` 需携带 `Authorization: Bearer <Gateway-Key>` 或 `x-api-key`，杜绝外部盗刷上游商业额度。本机回环 (`127.0.0.1`) 自动免密通行。
     - **⚡ 规范 HTTP 502/503 异常透传**：上游不可达或网络断连返回标准 `502 Bad Gateway`，无可用通道返回 `503 Service Unavailable`，严禁 Mock 假数据，确保下游客户端正常触发重试与降级。
     - **🔒 Prompt Cache 路由亲和**：维持适用分组的冷备状态，减少跨通道分流；独立通道设为冷备 (`schedulable=false, priority=10`)，跨组共享渠道自动保留全局调度开关，仅调低组内优先级 (`priority=10`)，杜绝跨组误杀，完美支持一个渠道挂载多个业务分组。
     - **💾 操作系统级原子写盘**：采用 `.tmp` + `fs.renameSync` 原子写入，彻底杜绝突发掉电或高频并发导致 JSON 配置文件损坏。
   - 自带控制台内嵌【智能代理分流验证测试器】，可随时发起真实调用检验分流效果。
   - 移动端小屏自适应优化，彻底消除 1664px 大宽度横向撑破。

4. **✈️ Telegram 机器人推送与移动端远程中控 (Telegram Bot Remote Console)**
   - **离机即时推送**：
     - 上游进货倍率变动实时告警（含涨跌幅度与变价渠道）。
     - **主力涨价高危警报**：当正在出海的主力通道被上游涨价时，Telegram 立即报警并在消息底部附带低价备选线路的**一键切换按钮**。
     - **自动切线报告**：当系统触发首字超时 (TTFT) 熔断或宕机自动切线时，推报警情并报告新旧倍率与延迟对比。
   - **手机端双向交互与一键切线**：
     - `/status`：查看当前主力通道、进货倍率、销售毛利率、延迟与自动切线状态。
     - `/switch`：弹出所有上游通道的 **Inline Keyboard 点击交互按钮**，在手机上点击任意渠道秒级完成调度切线。
     - `/auto`：在手机上一键开关自动切线保护，或切换成本优先/极速优先策略。
     - `/rates`：输出所有上游渠道进货倍率从低到高天梯榜。
     - `/check`：立即发起全量上游价格探针与测速巡检。
   - **安全与长轮询架构**：
     - 采用 Long Polling 长轮询，内网/Docker/VPS 免公网 IP、免域名与 SSL 证书即开即用。
     - 私聊使用 `/bind <控制台管理密码>`，或在控制台配置管理员个人 Telegram ID。`/start` 不会自动授权，通知群成员也不会因群已配置而获得管理权限。

## 🚀 启动方式

```bash
cd upstream-monitor
node server.js
```
或者运行脚本：
```bash
./scripts/start.sh
```

打开浏览器访问：`http://localhost:3300`

## 验收与架构边界

运行 `npm test` 执行隔离回归测试。CI 检查 JavaScript 语法并在构建后启动无生产卷的临时容器，验证认证状态接口可响应；这不代表生产部署已经验证。

数据库与 Redis 同步仍有同步子进程调用，慢查询或 SSH 等待可能阻塞事件循环。异步访问和后台任务拆分属于后续工作，完整范围见 [修复计划](../docs/repair-plan.md)。
